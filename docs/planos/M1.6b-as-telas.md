### Os tipos da API

O contrato é o de `backend/apps/api/serializers.py`, conferido pela revisão da spec. Decimais chegam
como **string** e são convertidos por `Number()` só na hora de formatar ou calcular; datas `AAAA-MM-DD`
e instantes ISO com deslocamento chegam como string.

```ts

  kind: "stock" | "index"; sector: string | null; status: "active" | "inactive";
  has_prices: boolean };
type AssetPage = { count: number; limit: number; offset: number; results: AssetItem[] };
type AssetDetail = AssetItem & { subsector: string | null; segment: string | null;
  listing_segment: string | null;
  last_price: { date: string; close: Dec; adj_close: Dec } | null };
type PriceRow = { date: string; open: Dec; high: Dec; low: Dec; close: Dec; adj_close: Dec; volume: number };
type Prices = { ticker: string; from: string | null; to: string | null; results: PriceRow[] };
type EventRow = { date: string; kind: "dividend" | "split"; amount: Dec | null;
  numerator: Dec | null; denominator: Dec | null };
type Events = { ticker: string; results: EventRow[] };
type HistogramBin = { bin_index: number; lower_bound: Dec | null; upper_bound: Dec | null; count: number };
type Metric = { calculated_at: string; as_of_date: string; first_price_date: string; price_count: number;
  /* as 26 colunas de METRIC_COLUMNS, Dec | string (datas) | number (contagens) | null */
  histogram: HistogramBin[] };
type Metrics = { ticker: string; metric: Metric | null };
type RiskResult = { model_name: ModelName; model_category: "traditional" | "garch" | "ml";
  alpha: "0.0500" | "0.0100"; hyperparameters: Record<string, unknown>;
  var_latest: Dec | null; var_mean: Dec | null; violations: number | null;
  expected_violations: Dec | null;
  kupiec_passed: boolean | null; kupiec_p_value: Dec | null;
  christoffersen_passed: boolean | null; christoffersen_p_value: Dec | null;
  dq_passed: boolean | null; dq_p_value: Dec | null;

  train_count: number; test_count: number;
```

### A conversão do VaR (RF-12)

```ts
export const lossFromVar = (v: number): number => 1 - Math.exp(-v);
```

Formatação da perda: percentual pt-BR com **uma** casa (`Intl.NumberFormat("pt-BR", { style:
"percent", minimumFractionDigits: 1, maximumFractionDigits: 1 })`). `"0.0500000000"` → `4,9%`. A
discordância e a tabela usam a mesma função; nenhum componente formata VaR por conta própria.

### Os estados do risco

`riskState(asset, risk, prices)` é função pura. `asset` é `{ state: "loading" } | { state: "error" }
| { state: "ok", status: "active" | "inactive" }`; `prices` é `{ state: "loading" } | { state:
"error" } | { state: "ok", count: number }`. O `404 asset_not_found` da identidade não chega aqui: a
tela inteira vira "ativo não encontrado" (RF-06). **A ordem das perguntas é o contrato:**

```
1. latest.status ∈ {ok, partial}        → in_progress ? E2 : E1
2. latest.status = failed                → E3  (com recálculo se in_progress)
3. in_progress                           → E4
4. request.status ∈ {queued, running}    → E5
5. request.status = done e reason começa por "serie curta"  → E6
6. request.status ∈ {failed, expired}    → E7
7. request.status = done (motivo "calculado", latest nulo — a reserva do RF-17) → E8
   (daqui para baixo: request nulo)
7a. asset.state = loading                → CARREGANDO  (skeleton, sem botão)
7b. asset.state = ok e status = inactive → E9
    (asset.state = error segue adiante: sem saber a situação, a tela oferece o pedido, e o POST
    responde 422 se o ativo for inativo — RF-19 leva ao E9)
8. prices.state = loading                → CARREGANDO  (skeleton, sem botão)
9. prices.state = error                  → E8
10. 1 ≤ prices.count ≤ MIN_SESSIONS − 1  → E6b
11. senão (0, ou ≥ MIN_SESSIONS)         → E8
```

`shouldPoll(risk) = risk.in_progress !== null || risk.request?.status ∈ {queued, running}`.

### O acompanhamento (RF-20)

Um gancho da tela do ativo: enquanto `shouldPoll` for verdadeiro, um `setTimeout` de **5000 ms** pede
o `/risk` de novo; `document.visibilityState === "hidden"` suspende, `visibilitychange` para
`visible` retoma com um pedido imediato; desmontar a tela cancela. **Quando `shouldPoll` passa de
verdadeiro a falso**, a tela recarrega as cinco rotas. O anúncio `aria-live` só muda de texto quando
`results_written`, o estado ou o `status` do pedido mudam. **A seção de risco expõe o estado em
`data-risk-state`**, lista fechada: `E1`…`E9`, `E6b`, `CARREGANDO` (linhas 7a e 8 da tabela),
`RISCO_CARREGANDO` (o próprio `/risk` na primeira carga) e `RISCO_ERRO` (o `/risk` falhou — o erro na
seção, RF-06). **O `reloadAll()` não apaga a seção**: enquanto as cinco rotas recarregam, a seção
continua mostrando o último `/risk` recebido, e o `data-risk-state` só muda quando o novo chega. É o
que a execução real e os testes leem.

### A busca (RF-05)

- pausa de **200 ms** antes da consulta;
- **o descarte da resposta atrasada**: cada consulta leva um número de sequência; a resposta só é
  aplicada se o número dela for o da última consulta disparada. Cancelar por `AbortController` é
  permitido **além** disso, não em vez — o teste simula a resposta antiga chegando depois da nova;
- página inicial: `limit=20`, "mostrar mais" com `offset += 20`; barra superior: `limit=8`;
- `role="combobox"` no campo, `aria-controls` na lista, `role="option"` em cada item, que contém
  um `<a href="/ativos/{TICKER}">`.

**A varredura do vocabulário proibido (V-09)**, em `frontend/tests/vocabulario.test.ts`:

```ts
const PROIBIDAS = /(?<![\p{L}\p{N}_])(melhor|melhores|recomendado|recomendada|recomendados|recomendadas|recomendamos|confiável|confiáveis)(?![\p{L}\p{N}_])/iu;
const ISENTAS = new Set(["rodape.ressalva"]); // a entrada que re-exporta ressalva.ts
```

Aplicada de duas formas, porque uma função de texto pode ter ramos que um único conjunto de valores
não exercita: (a) **sobre o texto-fonte** de todo arquivo de `frontend/src/content/` **menos
`ressalva.ts`**; e (b) sobre o resultado de cada entrada de `TEXTOS` e de cada tradução de
`motivos.ts`, com as funções chamadas pelos valores de uma tabela `EXEMPLOS` do próprio teste — uma
lista de argumentos por chave de função, que cubra cada ramo; **uma chave de função sem exemplos
reprova**. A ressalva mora em `ressalva.ts` e é re-exportada em `TEXTOS` como `rodape.ressalva`: a
forma (a) a isenta **pelo arquivo** e a forma (b) **pela chave** (`ISENTAS`), como o RF-14 diz.

**Nenhum texto visível em literal nos componentes** — `frontend/tests/jsx-texto.test.ts`, pela árvore
sintática, não por regex: cada `.tsx` de `frontend/src/` é lido com
`@babel/parser` (`sourceType: "module"`, `plugins: ["jsx", "typescript"]`), e a árvore é percorrida.
Reprova:

- um `JSXText` cujo conteúdo tenha uma letra (`/\p{L}/u`) — espaço, número e pontuação passam
  (`—`, `·`, `%`, `:`);
- **em posição que renderiza**, um `StringLiteral` com letra, ou uma parte fixa (`quasis`) com letra
  de um `TemplateLiteral`. Posição que renderiza é: o filho direto de um elemento JSX (`{"texto"}`), e,
  descendo **recursivamente** a partir dele, os dois ramos de `ConditionalExpression`, os operandos de
  `LogicalExpression` e as partes de `TemplateLiteral` — **não** desce em chamada de função, acesso a
  membro (`TEXTOS["risco.x"]`), objeto nem seta;
- a mesma regra no valor — literal ou dentro de `{…}` — **dos atributos de texto**, em qualquer
  elemento **ou componente**: `aria-label`, `aria-description`, `title`, `placeholder`, `alt`,
  `label`, `caption`, `hint`, `message`, `text`. **Componente próprio que receba texto recebe por uma
  dessas props**, ou por `children`; `className`, `href`, `data-*`, `role` e o resto não são texto.

A lista de exceções é vazia. O próprio teste tem casos de fixação (strings de código, no molde de

## Desvios do inventário da spec

- `frontend/src/theme.ts` e `frontend/src/risk/` não estão entre os cinco diretórios do inventário
  da spec (`api/`, `screens/`, `components/`, `content/`, `format/`). São lógica pura sem tela, e
  separá-los de `components/` é o que permite testá-los sem renderizar. **Acréscimo declarado**, dentro
  de `frontend/src/`, da cerca.
- `@babel/parser` em `devDependencies`: a spec pede a varredura de texto em JSX (V-09) e não fixa o
  meio; a regex reprovava TypeScript comum e deixava passar texto em várias linhas, e o `typescript`
  7 não expõe o compilador em JavaScript. `package.json` é arquivo comum, alteração aditiva.
- A isenção da ressalva no vocabulário é **pela chave** na forma (b), como a spec diz, e **pelo
  arquivo** na forma (a), que a spec não previa — a varredura do texto-fonte não tem chave.
- `frontend/tests/tokens.test.ts` é alterado **sempre** (a lista `INTERACTIVE`), não só "se houver
  token ou ícone novo": é o que faz o `:focus-visible` dos componentes novos ser verificado.
- A execução real **não muda o `vite.config.ts`**: a spec previa a possibilidade; a medida mostrou que
  a rede do próprio contêiner resolve.

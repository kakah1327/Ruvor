### Tarefa 4 — `prices.py`: laço por ativo, transação, rebusca, *upsert*

**Depende de:** T1, T3 · **Visual:** não

**Arquivos** — cria `prices.py`, `tests/assets/test_prices.py`

**Contrato** — tabela de decisões, mais o laço, que é a parte sutil e entra literal:

```python
def run_import_prices(source, tickers, *, full=False, now=timezone.now) -> PricesReport:
    assets, skipped = _resolve(tickers)                 # InvalidTickers antes de qualquer chamada
    if not assets:
        return PricesReport([_skipped(a) for a in skipped])   # sem collection_run
    run = CollectionRun.objects.create(source=SOURCE, started_at=now())
    results = [_skipped(a) for a in skipped]
    for asset in assets:
        results.append(_import_asset(source, run, asset, full=full, now=now))
    failed = any(r.error for r in results)
    run.status = CollectionRun.Status.FAILED if failed else CollectionRun.Status.OK
    run.error = ", ".join(r.ticker for r in results if r.error)
    run.finished_at = now()
    run.save(update_fields=["status", "error", "finished_at"])
    report = PricesReport(results)
    if failed:
        raise PricesFailed(report)
    return report


def _import_asset(source, run, asset, *, full, now) -> AssetResult:
    mode = _mode(asset, full)
    try:
        response = _fetch_and_store(source, run, asset, mode, now)      # forma (c): levanta
        conformed = _validate_and_conform(response)                      # formas (a)/(b): levanta
        if mode == "incremental" and _has_new_event(asset, conformed):
            mode = "completa"
            response = _fetch_and_store(source, run, asset, mode, now)
            conformed = _validate_and_conform(response)
        with transaction.atomic():
            counts = write_conformed(asset, run, conformed)              # forma (d): reverte
    except Exception as exc:  # (a)-(d): YahooClientError, InvalidResponse, e o que a gravacao levantar
        return AssetResult(asset.ticker, mode, ..., error=f"{type(exc).__name__}: {exc}")
    return AssetResult(asset.ticker, mode, len(conformed.bars) + conformed.discarded, conformed.discarded, counts.created, counts.updated, counts.events_created, None, False)
```

O bloco é esqueleto: nomes das funções auxiliares são livres, **exceto** `write_conformed`
(costura) e a ordem: buscar → gravar `bronze` → validar → conformar → decidir rebusca →
`atomic()` só em volta de `write_conformed`. `_fetch_and_store` grava `YahooChart` para toda
`ChartResponse` (200 ou não) **antes** de validar; com `YahooClientError` não há linha.
`InvalidResponse` é a exceção interna das formas (a)/(b), com a mensagem do relatório
(`HTTP 404: No data found, symbol may be delisted`).

`write_conformed`: `now = timezone.now()` uma vez no início (padrão do `_conform` do M1.1); para cada `Bar`, `log_return` pela regra da tabela de decisões; `Price`
existente → compara a tupla quantizada; diferente → escreve `run`, `updated_at = now`, conta
`updated`; ausente → cria com `run`, `updated_at`, conta `created`. Eventos: `get_or_create`
por `(asset, date, kind)`; criado → conta. Se `bars` é vazio (resposta só com nulos), nada
escrito, `WriteCounts(0, 0, n_eventos)`.

`_resolve(tickers)`: com argumentos, dedup + ordena; qualquer um ausente ou não-`active` →
`InvalidTickers(ofensores)`. Sem argumentos: `Asset.objects.filter(prices__isnull=False)
.distinct().order_by("ticker")`; os `inactive` viram `skipped`, os `active` são os `assets`.

`test_prices.py`, todos `@pytest.mark.django_db`, cenários compostos das fixtures pela regra da
spec (o terceiro ativo dos cenários de três recebe `PETR4_tail`; `meta.symbol` não é
validado): RF-02 (ok; falha (a) → `failed`, `PricesFailed` carrega o relatório). **Todo teste que espera

(c), o nome da exceção do fake na (d) — porque `_import_asset` captura `Exception`, e um cenário
mal montado (`AssertionError` da `FakeYahoo`) produziria "segundo falho, coleta `failed`"
exatamente como o teste espera; RF-03 (payload
`==` fixture; 404 gravado com `http_status 404`); RF-04 (`XXXX9` e inativo → `InvalidTickers`,

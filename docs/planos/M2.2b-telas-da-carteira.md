## O que este plano decide

### A aritmética dos pesos (RF-06) — literal, a falha é silenciosa

`frontend/src/portfolio/weights.ts`, só funções puras:

```ts
/** O peso digitado em centésimos inteiros; nulo se não for um peso com até 2 casas. */
export function parseWeight(text: string): number | null;
/** Os centésimos de volta ao texto que a API recebe: 3333 -> "33.33", 500 -> "5.00". */
export function weightToApi(cents: number): string;
/** A soma, em centésimos inteiros. */
export function sumCents(weights: readonly number[]): number;
export const TOTAL_CENTS = 10_000;
```

- `parseWeight` **lê o texto por dígitos**, não por `parseFloat`: apara os espaços das pontas, troca a vírgula por ponto,
  aceita `^\d{0,3}([.]\d{0,2})?$` com ao menos um dígito no total, separa a parte inteira e a decimal e devolve
  `inteira * 100 + decimal` (a inteira vazia vale 0; a decimal completada à direita: `"5,1"` → 510, `",5"` → 50, `"5,"` →
  500). `"0,29"` → 29, `"1,15"` → 115 (por `parseFloat × 100` truncado sairiam 28 e 114).
- **O editor guarda o texto digitado como valor do campo** e deriva os centésimos dele — nunca reescreve o campo ("5,"
  continua "5,", não vira "5.00"). A soma é `sumCents(...) === TOTAL_CENTS` — **nunca** comparação de `number` em ponto
  flutuante. `0,01 + 65,40 + 34,59` dá 10.000 (em ponto flutuante, `100.00000000000001`).

### A fonte do risco (RF-09, RF-11) — literal, a falha é silenciosa

`frontend/src/portfolio/useRiskSource.ts`: a página guarda **o último dado bom e o erro em separado**, porque o
`useResource` de hoje (`frontend/src/api/resource.ts`) troca o dado por `{state: "error"}` quando a releitura falha:

```ts
export type RiskSource = {
  data: PortfolioRisk | null;      // o último corpo bom (a leitura ou o 202)
  firstError: ApiError | null;     // só o erro da primeira leitura
  notFound: boolean;               // um 404 em qualquer leitura: a página vai a "não encontrada"
  loading: boolean;                // a primeira leitura ainda não voltou
  attempt: number;                 // sobe a cada resposta, boa ou com erro — reagenda a consulta
};
export function useRiskSource(portfolioId: string): {
  source: RiskSource;
  reload(): void;                  // um GET .../risk
  accept(body: PortfolioRisk): void; // o corpo do 202 entra como a leitura (sobe o attempt)
};
```

- Uma releitura com erro **mantém o `data`** e sobe o `attempt`; só a primeira leitura grava `firstError`.
- **401** em qualquer leitura chama o `expired()` do M2.1b; **404** zera o `data` e liga `notFound` — a página vai a
  "carteira não encontrada" (RF-02) e a consulta para (`value` nulo). Esses dois não "mantêm o estado".
- **Só vale a resposta do pedido mais recente**: uma resposta de pedido já substituído (uma consulta que volta depois de um
  `reload()`) é descartada, como no `resource.ts`.
- O corpo do **202** entra por `accept` (a API o lê depois do commit: spec do M2.2a); o `409 portfolio_risk_up_to_date`
  chama `reload()` (o 409 só traz `details.run_id`).
- **Depois de um `PUT` que muda a versão, e de um `PATCH` do valor, a página chama `reload()`**: o `GET .../risk` lê só a
  versão corrente, e a perda em reais é calculada na leitura com o valor de agora.
- **A seção só mostra um `data` da versão corrente**: com `data.version !== portfolio.version` (o corpo do risco traz
  `version`), a seção mostra "carregando" — ou o erro, se a releitura depois do `PUT` falhou —, nunca o resultado da versão
  anterior ao lado da composição nova (RF-07).

### A ordem dos estados do risco (RF-09) — literal na ordem

`frontend/src/portfolio/riskState.ts`:

```ts
export type PortfolioRiskState =
  | { kind: "loading" }
  | { kind: "error"; error: ApiError }                  // só a primeira leitura
  | { kind: "result_recalculating"; latest: PortfolioRun; progress: PortfolioProgress }
  | { kind: "calculating"; progress: PortfolioProgress; failed: PortfolioRun | null }
  | { kind: "ready"; latest: PortfolioRun }             // ok ou partial
  | { kind: "failed"; latest: PortfolioRun }
  | { kind: "never" };

export function portfolioRiskState(source: RiskSource, version: number): PortfolioRiskState;
export function shouldPollPortfolio(risk: PortfolioRisk): boolean; // in_progress !== null
```

**A ordem das perguntas é a da tabela do RF-09**: `loading` (ou `data.version !== version` sem erro); `data` nulo e
`firstError` (ou `data.version !== version` com a releitura em erro) → `error`; `latest` `ok`/`partial`
**e** `in_progress` → `result_recalculating`; `in_progress` → `calculating`; `latest` `ok`/`partial` → `ready`; `latest`
`failed` → `failed`; senão `never`. `PortfolioRisk` é o corpo interno de `{portfolio_risk: …}`.

### A consulta repetida (RF-17, D-182) — literal

`frontend/src/risk/usePolling.ts` ganha a forma genérica, e a tela do ativo passa a chamá-la com o comportamento de hoje:

```ts
export function usePolling<T>(
  value: T | null,
  shouldPoll: (v: T) => boolean,
  reload: () => void,
  onEnd: () => void,                 // o ativo: reloadAll (recarrega as rotas); a carteira: nada
  attempt?: number,                  // a carteira: o attempt da fonte; o ativo: ausente
): void;
```

- O efeito depende de `value` **e** de `attempt`: cada resposta — inclusive a de erro, que mantém o `value` e sobe o
  `attempt` — reagenda o próximo `reload` em `POLL_INTERVAL_MS = 5000` enquanto `shouldPoll(value)` for verdadeiro.
- **O ativo segue igual:** `value` nulo (o `/risk` em erro) para a consulta, como hoje ("o tentar de novo retoma"), sem
  `attempt`; ao terminar, `onEnd()` recarrega as rotas. **A suíte da tela do ativo segue verde sem mudar teste**
  (nenhum teste importa o hook; o `estados.test.ts` usa o `shouldPoll` de `risk/state.ts`, que fica).
- **A carteira** passa o `attempt` da fonte: um erro (rede, 5xx, 429) numa releitura mantém o `value` e sobe o `attempt`,
  e a consulta segue. A suspensão na aba oculta continua.

### Os tipos e os componentes compartilhados (RF-15, RF-16)

Em `frontend/src/api/types.ts`: `RiskResultBase` — os campos que `ModelTable.tsx`, `LossSummary.tsx` e

`error`) e os que a carteira também traz (`hyperparameters`, `var_mean`) —, com `RiskResult = RiskResultBase &

`PortfolioRiskResult = RiskResultBase & {loss_brl: string | null}`; os tipos da carteira (`Portfolio`, `PortfolioPage`,
`PortfolioRisk`, `PortfolioRun`, `PortfolioProgress`, `PortfolioSummary`) com os campos dos serializadores do M2.2a.

A superfície nova dos compartilhados, **com as props opcionais ausentes no ativo** (a tela e os testes do ativo não

ModelTable<R extends RiskResultBase>({ results, lossBrl }: { results: readonly R[]; lossBrl?: (r: R) => string | null })

- **A taxa:** o caminho é logado — limita a `user` (600/min) e a `auth`; o roteiro não sobe nenhuma.
- **As ações:** duas com 503 pregões ou mais (ex.: ITUB4 e PETR4) e **uma ação ativa sem preço**, para o
  `insufficient_history` com o link — a T0 mede as duas listas.

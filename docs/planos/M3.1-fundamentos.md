## Como ler este plano

[PROCESSO §5](../PROCESSO.md#5-anatomia-de-um-plano): contratos, não corpos. Literal só onde é
contrato (`db_table`, restrições, assinaturas de costura, rótulos do relatório, o hash) ou onde a
falha é silenciosa (a tabela de contas, o trimestre isolado, o 4º trimestre, a escala das ações,
a ordem dos motivos). O padrão a imitar é o do M1.2 — `yahoo.py`, `conform_prices.py`,
`prices.py`, `tests/assets/conftest.py` — e o do M1.3 para o cálculo (`analytics/compute.py`,
`MetricsFailed`), e este plano cita o que copiar em vez de repetir.

**Todo critério roda no contêiner `worker`** — desde o M1.4 é onde a suíte e o `mypy` do backend
rodam (ESTADO). Exceções, declaradas na tarefa: a V-07 e a V-12, que rodam no hospedeiro. No Git
Bash, `docker compose exec -w …` precisa de `MSYS_NO_PATHCONV=1`
([aprendizados](../aprendizados.md)); os critérios abaixo não usam `-w`.

O hash, literal (RF-06):

```python
def content_sha256(payload: bytes) -> str:
    digest = hashlib.sha256()
    with zipfile.ZipFile(io.BytesIO(payload)) as zf:
        for name in sorted(zf.namelist()):
            digest.update(name.encode("utf-8"))
            digest.update(b"\0")
            digest.update(zf.read(name))
    return digest.hexdigest()
```

**As fixtures.** `recortar.py` roda **no hospedeiro ou no `worker`, com rede, à mão** — nunca na
suíte (não se chama `test_*`). Para cada zip de origem, baixa, e grava um zip novo com **todos os
membros de mesmo nome**, cada um contendo o cabeçalho e **só as linhas** cujo `CD_CVM` (ou, na
`composicao_capital` e no `parecer`, que não têm `CD_CVM`, o `CNPJ_CIA`) é de uma companhia do
recorte — bytes das linhas copiados sem
decodificar e recodificar, para manter o latin-1 e o fim de linha. Recortes, pela spec:

| Fixture | Origem | Companhias |
|---|---|---|
| `itr_2024.zip`, `dfp_2024.zip` | ITR 2024, DFP 2024 | Petrobras, Vale, Itaú, Bradesco, BB Seguridade, Vivara, Sanepar, BNB, Camil |
| `itr_2025.zip` | ITR 2025 | Petrobras |
| `dfp_2025.zip` | DFP 2025 | Camil |
| `itr_2019.zip` | ITR 2019 | Petrobras |
| `itr_2016.zip` | ITR 2016 | BB Seguridade |

anotações completas.

3. **Escopo** (RF-09): `consolidated` se há linha em `bpa_con`, `bpp_con` ou `dre_con` depois do

4. **Escala** (RF-11): `MIL` × 1000, `UNIDADE` × 1, outra → `ValueError(f"ESCALA_MOEDA {v}")`.

```python
def infer_share_scale(L: Decimal, N: int, E: Decimal) -> int | None:
    if not L or N <= 0 or not E or (L / E) < 0:
        return None
    best = min((1, 1000), key=lambda k: abs(math.log(float(L / (N * k) / E))))
    return best if abs(math.log(float(L / (N * best) / E))) < math.log(2) else None
```

  `share_composition = bool(capital)`; `shares_on`/`shares_pn` = (integralizado − tesouraria)

### Tarefa 5 — `importer.py`: coleta, anos a conformar, transação, reconformação

**Depende de:** T1, T4 · **Visual:** não

**Arquivos** — cria `importer.py`, `tests/fundamentals/test_importer.py`

**Contrato** — `run_import_fundamentals(source: CvmSource, *, full: bool = False, reconform:
list[int] | None = None, now: Callable[[], datetime] = timezone.now) -> ImportReport`.
`reconform=[]` quer dizer "todos os anos"; `None` quer dizer coleta normal. `full` e `reconform`
juntos → `ValueError`.

O laço, esqueleto (nomes auxiliares livres, **exceto** `write_company_year`; a ordem é contrato):

```python
def run_import_fundamentals(source, *, full=False, reconform=None, now=timezone.now) -> ImportReport:
    run = CollectionRun.objects.create(source=SOURCE, started_at=now())    # SOURCE = "cvm-dados-abertos"
    files: list[FileResult] = []
    changed_years: set[int] = set()
    new_companies: set[str] = set()
    if reconform is None:
        new_companies = _new_catalog_companies(run)                        # RF-17 (b): ANTES de (a), sem Company no inicio
        for kind, year in _range(now):                                     # RF-03: por ano crescente, itr antes de dfp
            result = _collect(source, run, kind, year, full=full, now=now) # RF-04/05; nunca levanta
            files.append(result)
            if result.status == "novo":
                changed_years.add(year)
        years = _years_to_conform(changed_years, now)                      # RF-17 (a): A e A+1, dentro do intervalo
    else:
        years = set(reconform) or set(_all_years(now))
    year_results = [_conform_year(run, y, now) for y in sorted(years)]
    if reconform is None and new_companies:
        rest = sorted(set(_all_years(now)) - years)                        # so os anos que (a) nao conformou
        year_results += [_conform_year(run, y, now, only=new_companies, label="novas") for y in rest]
    report = ImportReport(files, year_results, ...)
    _close(run, report, now)                                                # ok | failed, error
    if report.failed:
        raise FundamentalsImportFailed(report)
    return report
```

- **Ordem de (a) e (b)**: o conjunto de novas é calculado **antes** de (a) — as do catálogo sem
  `Company` no **início** da execução —, e (b) conforma para elas **só os anos que (a) não
  conformou**. Assim a companhia nova recebe o histórico inteiro mesmo quando (a) conforma o ano
  corrente na mesma coleta (quase toda semana), e nada é conformado duas vezes: na carga inicial
  (a) cobre todos os anos e `rest` sai vazio. A companhia que falhou em (a) no ano A não é
  refeita em A por (b) — A está em `years`; um ano que falhou no nível do ano em (a) também não
  é relido por (b). `_conform_year` ganha dois parâmetros opcionais: `only: set[str] | None` (o
  laço de companhias se restringe a elas) e `label` (`"ano"` ou `"novas"`, o prefixo da linha do
  relatório).
- `_collect`: `HEAD`; decide pelo "último visto" (maior `id` com 200 e `content_sha256` não
  nulo); `GET`; `content_sha256` — `BadZipFile` → linha sem `payload` nem hash, `FALHOU`; hash
  igual ao da versão corrente → linha **sem** `payload`, `inalterado`; senão linha **com**
  `payload`, `novo`. Todo `GET` com status ≠ 200 grava linha sem `payload` nem hash (RF-05). 404 do
  ano corrente (no `HEAD` ou no `GET`) → `ausente`, sem falha; 404 de outro ano, outro status ≠ 200
  e `CvmClientError` → `FALHOU`. `CvmClientError` não deixa linha. `_collect` captura só
  `CvmClientError` e `BadZipFile` — nunca `Exception`: um `AssertionError` da `FakeCvm` tem de
  estourar o teste, não virar `FALHOU`.
- `_conform_year(run, year, now)`: lê a versão corrente de ITR e DFP de `year` e de ITR de `year
  - 1` (a que existir); para cada companhia do catálogo (RF-07) presente em algum dos três
  índices, monta os `DocumentRows`, chama `conform_year` (T4) **fora** do `atomic()`, e
  `with transaction.atomic(): counts = write_company_year(...)`. Exceção em qualquer ponto da
  companhia → `FALHOU`, as outras seguem. Ler cada zip **uma vez por ano**, agrupando as linhas
  por `CD_CVM` em fluxo — não reabrir o zip por companhia. **Falha no nível do ano** — a
  leitura dos zips do ano levanta (membro faltando, CSV quebrado) antes do laço de companhias —
  vira `ano {A}: FALHOU ({Classe}: {msg})`, o ano não conforma nada, os outros anos seguem, e a
  coleta termina `failed`; a `collection_run` nunca fica `running`.
- `write_company_year`: `Company` **sem** `update_or_create` — lê a existente, compara `cnpj`,

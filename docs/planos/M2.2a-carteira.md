## Como ler este plano

[PROCESSO §5](../PROCESSO.md#5-anatomia-de-um-plano): contratos, não corpos. Literal só onde é
contrato (colunas, `db_table`, nomes no banco, o SQL dos gatilhos, as assinaturas, os nomes das

### A série — literal, porque a falha é silenciosa

```python
def compute(prices, weights):
    tickers = sorted(weights)                       # a soma sai sempre na ordem do ticker
    by_date = {t: dict(prices[t]) for t in tickers}
    dates = sorted(set.intersection(*(set(by_date[t]) for t in tickers)))
    index = [1.0] if dates else []
    w = {t: float(weights[t]) / 100 for t in tickers}           # float(Decimal) / 100, nessa ordem
    for prev, cur in zip(dates, dates[1:]):
        r = 0.0
        for t in tickers:
            r += w[t] * (float(by_date[t][cur]) / float(by_date[t][prev]) - 1)
        index.append(index[-1] * (1 + r))
    return tuple(dates), tuple(index)

def series_sha256(dates, index):
    text = "".join(f"{d.isoformat()}|{v!r}\n" for d, v in zip(dates, index, strict=True))
    return hashlib.sha256(text.encode("utf-8")).hexdigest()
```

`build` lê `Price.objects.filter(asset__in=..., adj_close__gt=0)` (com `first`/`last` como filtro de
data, inclusivo), monta `prices` por ticker com `(date, adj_close)`, chama `compute` e o hash, e
calcula `coverage` e `price_run_id` (*O que este plano decide*). **Uma consulta**, ordenada por
`asset__ticker, date`. As posições vêm de `version.holdings` (gerente com escopo: quem chama já está
sob `organization_scope`, inclusive os testes); **toda** posição entra em `prices`, a sem preço com a
lista vazia — `compute` faz `prices[t]` para cada ticker, e a interseção com uma lista vazia é vazia. A web e o `worker` passam pelo mesmo `build`: é o que garante o mesmo hash.

### A perda em reais — literal

```python
_CENT = Decimal("0.01")

def loss_brl(notional, var):
    if notional is None or var is None:
        return None
    return (notional * (1 - (-var).exp())).quantize(_CENT, rounding=ROUND_HALF_UP)
```

`Decimal.exp()` no contexto padrão (28 dígitos). `var` é o `Decimal(18, 10)` da coluna, nunca
`float`.

### A escrita sob a trava — literal na ordem

```python
def _write(run_id: int, model_name: str, rows: Callable[[PortfolioRiskRun], list[PortfolioRiskResult]]) -> None:
    with transaction.atomic():
        lock_run(run_id)
        _after_run_lock()
        run = PortfolioRiskRun.objects.get(pk=run_id)        # releitura simples, sem select_for_update
        if run.status != RiskRun.Status.RUNNING:
            logger.info("carteira run=%d modelo=%s: execucao ja fechada; descartado", run_id, model_name)
            return
        if run.results.filter(model_name=model_name).exists():
            return                                             # reentrega que chegou ao mesmo tempo
        PortfolioRiskResult.objects.bulk_create(rows(run))
```

Os três caminhos da tarefa por modelo — o resultado bom, o `"serie mudou"` e a exceção —
**terminam** em `_write`; nenhum grava por outro lugar. O fecho e a abertura seguem a mesma ordem:
`atomic`, `lock_run`, o ponto de desvio (só o fecho), a releitura, a decisão.

### A abertura — literal na ordem, porque levantar dentro do `atomic` desfaz o fecho

```python
def _abrir_risco_carteira(run_id, organization_id):
    load_all_model_modules(); load_all_backtest_modules()
    with organization_scope(organization_id):
        missing: list[str] = []
        with transaction.atomic():
            lock_run(run_id)
            run = PortfolioRiskRun.objects.get(pk=run_id)
            if run.status != RiskRun.Status.RUNNING or run.engine_version:
                return                            # fechada, ou abertura reentregue: já enfileirou
            missing = [m for m in run.requested_models if m not in list_models()]
            if missing:
                _close_failed(run)                # status failed, finished_at now
            else:
                run.engine_version = version("ruvor-engine")
                run.save(update_fields=["engine_version"])
        if missing:
            raise ModelsMissing(missing)          # depois do commit: o failed fica gravado
        by_cost = sorted(run.requested_models, key=lambda n: _RANK[get_model(n).category])
        group = chord([calcular_modelo_carteira.si(run_id, organization_id, n) for n in by_cost],
                      fechar_risco_carteira.s(run_id, organization_id))
        try:
            _enqueue(group)                       # fora do atomic: a linha já está commitada
        except Exception:
            with transaction.atomic():
                lock_run(run_id)
                run = PortfolioRiskRun.objects.get(pk=run_id)
                if run.status == RiskRun.Status.RUNNING:
                    _close_failed(run)
            raise
```

`_RANK = {ModelCategory.TRADITIONAL: 0, ModelCategory.GARCH: 1, ModelCategory.ML: 2}`. A condição
`run.engine_version` vazio é a do RF-04 ("enquanto `running` e vazia"): a abertura reentregue pelo
Celery não regrava a versão nem enfileira um segundo `chord`. Sem
`on_commit` aqui: o `_enqueue` roda depois do `with atomic`, e a falha dele é tratada no próprio
fluxo.

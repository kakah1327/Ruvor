### A lista de episódios (literal — é o contrato da D-147)

Em `backend/apps/analytics/stress.py`:

```python
STALE_START_DAYS = 10


@dataclass(frozen=True)
class Episode:
    code: str
    start: date
    end: date


EPISODES: tuple[Episode, ...] = (
    Episode("jbs_2017", date(2017, 5, 17), date(2017, 6, 30)),
    Episode("truckers_2018", date(2018, 5, 18), date(2018, 6, 29)),
    Episode("covid_2020", date(2020, 2, 21), date(2020, 3, 31)),
    Episode("rates_2021", date(2021, 6, 7), date(2022, 7, 14)),
```

### A definição, com as bordas (literal — a falha é silenciosa)

O módulo recebe três séries ordenadas por data — a do ativo (`bars`, nunca vazia: `_compute_asset` pula a vazia
antes), a de comparação (`benchmark`, o IBOV ou `None`; `None` também quando o ativo é o próprio IBOV) e o
**calendário** (`calendar`, a série do IBOV quando existe, **inclusive quando o ativo é o próprio IBOV**; senão `None`) —
e devolve um `EpisodeResult` por episódio de `EPISODES`, na ordem da tupla. **`bars[-1]` é o último pregão da série
inteira**, não o da janela: `ends_before` só dispara com a série terminando dentro do episódio.

**O motivo**, avaliado nesta ordem, o primeiro que se aplica (RF-03):

```python
def missing_reason(bars, ep, calendar) -> str | None:
    base = [b for b in bars if b.date <= ep.start]
    if not base:
        return "starts_after"
    if (ep.start - base[-1].date).days > STALE_START_DAYS:   # 10 dias: sem motivo; 11: stale_start
        return "stale_start"
    market = [b for b in (calendar or []) if b.date <= ep.end]
    market_end = market[-1].date if market else ep.end
    if bars[-1].date < market_end:
        return "ends_before"
    if not any(ep.start < b.date <= ep.end for b in bars):
        return "no_trading"
    return None
```

**As medidas**, só quando o motivo é `None`, sobre `adj_close` (RF-04):

- `p0` = último de `bars` com `date ≤ start`; `pn` = último com `date ≤ end`; `window = [b for b in bars if p0.date
  ≤ b.date ≤ pn.date]`.
- `period_return = (pn.adj_close / p0.adj_close - 1).quantize(Q10)`.
- A queda: percorre `window` com o topo corrente atualizado **antes** de medir a queda do pregão — o laço do
  `max_drawdown` do M1.3 —, topo trocado só por **estritamente maior**, profundidade trocada só por **estritamente
  menor** (primeiras ocorrências). `drawdown = depth.quantize(Q10)`.
- **Queda zero decide pelo valor quantizado**: `drawdown == 0` → `drawdown_peak_date = drawdown_trough_date =
  p0.date`, `recovery_date = recovery_sessions = None`. Assim o que a tela lê como "sem queda" é o que está gravado.
- A recuperação, com `drawdown < 0`: em `bars` — **a série inteira** —, o primeiro índice `j` depois do índice do fundo
  com `bars[j].adj_close >= adj_close(topo)`; `recovery_date = bars[j].date`, `recovery_sessions = j − i_fundo`, os
  índices **da série inteira**. Sem `j`: os dois nulos.

**O índice** (RF-05): as mesmas medidas sobre `benchmark`, com o motivo avaliado por
`missing_reason(benchmark, ep, calendar=None)` — a regra da spec: sem calendário, o `ends_before` do índice compara com
a própria data de fim, e só dispara com a série do índice terminando dentro do episódio. **Não** `calendar=benchmark`:
com o índice como calendário de si mesmo, `ends_before` nunca dispararia, e o índice com a série cortada mediria uma
janela parcial em silêncio, contra o RF-03. Com o motivo do índice não nulo, ou `benchmark is None`, as três colunas
de benchmark são `None`. **O índice não depende do motivo do ativo.**

O `EpisodeResult` carrega os campos da tabela do RF-07 menos `metric`, com `start_date`/`end_date` copiados do
`Episode`.

### Tarefa 0 — O oráculo

**Depende de:** nada · **Visual:** não · **Arquivos:** nenhum (o relato vai ao orquestrador, que o registra em "O que já
foi medido")

**Contrato** — **uma conta independente do código**, por SQL, só leitura, para a T8 confrontar: para o IBOV e a PETR4,
nos quatro episódios. **A consulta, literal** (um episódio por vez, pelas variáveis do `psql`: `docker compose exec -T postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v t=PETR4 -v ini=2020-02-21 -v fim=2020-03-31 -f -' < oraculo.sql`, com a consulta num arquivo do scratchpad, fora do repositório; no SQL, `:'t'`, `:'ini'` e `:'fim'`, que o `psql` põe entre aspas):

```sql
with s as (
  select p.date, p.adj_close,
         row_number() over (order by p.date) as i          -- índice na série inteira
  from silver.price p join silver.asset a on a.id = p.asset_id
  where a.ticker = :'t'
),
p0 as (select max(date) as d from s where date <= :'ini'),
pn as (select max(date) as d from s where date <= :'fim'),
w as (                                                     -- a janela, filtrada ANTES do topo corrente
  select s.* from s, p0, pn where s.date between p0.d and pn.d
),
t as (
  select w.*,
         max(adj_close) over (order by date rows unbounded preceding) as topo
  from w
),
q as (
  select t.*, adj_close / topo - 1 as queda,
         (select min(t2.date) from t t2 where t2.date <= t.date and t2.adj_close = t.topo) as data_topo
  from t
),
fundo as (                                                 -- a menor queda; no empate, a menor data
  select * from q order by queda asc, date asc limit 1
)
select (select d from p0) as p0, (select d from pn) as pn,
       (select adj_close from s where date = (select d from pn))
         / (select adj_close from s where date = (select d from p0)) - 1 as period_return,
       f.queda as drawdown, f.data_topo as peak_date, f.date as trough_date,
       r.date as recovery_date, r.i - f.i as recovery_sessions
from fundo f
left join lateral (                                        -- estritamente depois do fundo, na série inteira
  select s.date, s.i from s
  where s.i > f.i and s.adj_close >= (select adj_close from s where date = f.data_topo)
  order by s.i limit 1
) r on f.queda < 0;
```

Com `drawdown = 0`, a consulta devolve o primeiro pregão da janela como fundo e nenhuma recuperação — o mesmo que o
RF-04 manda gravar (topo e fundo em P0). E a escolha do ativo do mockup: a ação, entre as cinco com preço, cujos quatro
episódios mostram mais contraste com o IBOV.

**Critério de aceite** — o relato com a consulta e a saída literal, os oito conjuntos (dois ativos × quatro episódios).

**Cerca** — nenhuma escrita no banco nem no repositório.

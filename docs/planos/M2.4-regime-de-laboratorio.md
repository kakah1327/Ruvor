colunas, as restrições, o corpo da rota, a ordem dos estados — e o que **falha em silêncio**: o corte da década em `<`

### Os estados da seção (RF-14) — literal na ordem

`frontend/src/lab/state.ts`:

```ts
export type LabState =
  | "LOADING" | "ERROR" | "READY" | "FAILED" | "PENDING" | "INACTIVE" | "NO_DECADE" | "SHORT" | "NO_RISK";

export function labState(load: Load<Lab>): LabState {
  if (load.state === "loading") return "LOADING";
  if (load.state === "error") return "ERROR";
  const lab = load.data;
  if (lab.latest !== null) return "READY";
  if (lab.last_failure !== null) return "FAILED";
  if (lab.pending) return "PENDING";
  if (!lab.active) return "INACTIVE";
  if (lab.decade.first_price_date !== null && !lab.decade.complete) return "NO_DECADE";
  if (lab.decade.complete && lab.decade.sessions < MIN_SESSIONS) return "SHORT";
  return "NO_RISK";
}

/** A nota do estado READY: no maximo uma, nesta ordem (RF-14, linha 3). */
export function readyNote(lab: Lab): "failure" | "engine" | "partial" | null {
  const latest = lab.latest!;
  if (lab.last_failure !== null) return "failure";      // a rota so o devolve se posterior ao latest
  if (lab.active && lab.risk_engine_version !== null && latest.engine_version !== lab.risk_engine_version)
    return "engine";                                    // promete o experimento novo: so com o ativo `active`
  if (latest.status === "partial") return "partial";
  return null;
}
/** A promessa de nova tentativa (estados FAILED e notas failure/partial): so com `lab.active`; a nota do motor,
 *  que promete o experimento novo, nem aparece no inativo. */
```

### A execução real — literal

Do orquestrador, em duas fases. Antes de cada uma: ninguém usa o checkout principal; **o Beat parado**
(`docker compose stop beat`) do começo ao fim da fase; nenhum pedido sob demanda aberto; o `sha256sum .env` anotado,

rodar o código do ramo (aprendizado "O `worker` roda o código de quando subiu").

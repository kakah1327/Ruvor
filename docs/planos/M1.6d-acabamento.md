### Onde cada comando roda

| O quê | Onde |
|---|---|
| `npm test`, `npm run lint`, `npm run typecheck` | contêiner `frontend`: `docker compose exec -T frontend …` |
| `pytest`, `mypy`, `ruff` do backend | contêiner `worker`: `docker compose exec -T worker …` (o diretório de trabalho é `backend/`) |

**O `compose` monta o checkout principal, não o worktree** (aprendizado "O worktree não é o que o contêiner
monta"). Os comandos da tabela valem **só com o checkout principal neste ramo**, e quem o troca de ramo é o
orquestrador, que confirma antes que nenhum outro bloco o usa. Fora disso, cada comando roda, a partir do checkout
principal, num contêiner avulso com o worktree montado por cima, no molde do aprendizado: `MSYS_NO_PATHCONV=1
docker compose run --rm --no-deps -v "<worktree>/backend:/repo/backend" -v "<worktree>/engine:/repo/engine" worker
sh -c "…"` para o backend, e `MSYS_NO_PATHCONV=1 docker compose run --rm --no-deps -v
"<worktree>/frontend:/repo/frontend" -v /repo/frontend/node_modules frontend sh -c "…"` para o frontend (o volume
anônimo preserva o `node_modules` da imagem).

**Todo critério começa por uma guarda** de que o código montado é o deste ramo: `test -f` do arquivo que a tarefa
cria (`tests/biome.test.ts` na T3, `tests/test_dependencias.py` na T4) ou, nas tarefas que só alteram,
`grep -c 'aria-live="polite">{body}' src/components/RiskSection.tsx` devolvendo `0` depois da mudança. Sem a
guarda, o Vitest trata os caminhos como filtro e roda só os arquivos que existem no checkout montado, saindo verde
sem ter rodado o teste novo.

**O banco de teste é um só na máquina.** Outra frente pode estar usando o `worker` e o banco de teste ao mesmo
tempo (aprendizado "Duas suítes no mesmo `worker` usam o mesmo banco de teste"). A T4 só roda um arquivo que não
toca o banco; a suíte inteira do backend, na T5, espera o orquestrador confirmar que nenhuma outra suíte roda.

## O que este plano decide

### A região viva do risco (RF-01)

- Uma função pura, no mesmo arquivo `RiskSection.tsx`, recebe o estado e o `/risk` e devolve o texto da região
  ou `""` — a tabela do RF-01, na ordem dele. O `switch` do corpo não muda; o painel visível continua
  mostrando o mesmo texto.
- A região é `<p className="ruvor-sr-only" aria-live="polite">{texto}</p>`, **sempre montada** (vazia quando
  não há andamento): uma região viva criada junto com o texto não é anunciada pelos leitores de tela.
- Sem `role`. O embrulho do corpo continua existindo, sem `aria-live`.

### Como o teste acha a região (V-01, V-02) — literal

Dentro da seção, **exatamente um** elemento com o atributo `aria-live`, e ele **não contém** o corpo:

```ts
const vivas = section().querySelectorAll("[aria-live]");
expect(vivas).toHaveLength(1);           // risco: a região; Fundamentos e Comunicados: 0
const viva = vivas[0];
expect(viva.classList.contains("ruvor-sr-only")).toBe(true);
expect(viva.querySelector("table, .ruvor-panel")).toBeNull();
expect(viva.textContent).toBe(esperado);  // "" no E1
```

Em Fundamentos e Comunicados o comprimento esperado é **0**, no estado pronto e no carregando. O
`role="status"` não conta, porque é papel e não atributo `aria-live`; a região nova não o tem, e é isso que
mantém `risco.test.tsx:1036` e `:1109` de pé.

### A normalização do nome (RF-05) — literal

```python
import re

_NOME = re.compile(r"^\s*([A-Za-z0-9][A-Za-z0-9._-]*)")


def _nome(requisito: str) -> str:
    """'Pandas[performance]>=2 ; python_version>"3"' -> 'pandas' (PEP 503)."""
    achado = _NOME.match(requisito)
    assert achado is not None, f"requisito ilegivel: {requisito!r}"
    return re.sub(r"[-_.]+", "-", achado.group(1)).lower()
```

As listas lidas: `project.dependencies` e **cada** valor de `project.optional-dependencies`, reunidas numa
lista só, com a origem de cada entrada na mensagem de falha. A lista proibida é a `_BIBLIOTECAS` de
`tests/test_versoes_travadas.py`, mas **não é importada**: aquele módulo importa `engine.models` e
`apps.risk`, e o teste novo arrastaria o motor e o Django. A lista é copiada como tupla literal no teste novo,
com um comentário que aponta a origem, e **um segundo teste** lê o texto de `test_versoes_travadas.py` por `ast` e confere que a
tupla `_BIBLIOTECAS` de lá é igual à daqui — assim a cópia não envelhece calada (aprendizado "lista fechada
envelhece calada").

### O Biome (RF-03, RF-04)

Troca manual de uma linha: `"recommended": true` → `"preset": "recommended"`, no mesmo lugar dentro de
`linter.rules`. Não se roda `biome migrate`. O teste novo lê `../biome.json` com `JSON.parse` — o arquivo é
JSON puro hoje; se um dia ganhar comentário, o teste quebra por leitura, e isso é aviso, não falha silenciosa.
